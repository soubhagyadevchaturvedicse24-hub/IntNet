# Observation Adapter Benchmark Interface Specification

**Document Version:** 1.0.0  
**Status:** `[EXPERIMENTAL / BENCHMARK SPECIFICATION]`  
**Date:** 2026-09-06  
**Scope:** Phase 1 Forensic Observation Evaluation (Autopsy vs IPED)  

---

## 1. Important Architectural Distinction

> [!IMPORTANT]
> **Experimental Benchmark Adapter vs Future Production Adapter**  
> The observation adapters specified in this document are **EXPERIMENTAL BENCHMARK BOUNDARIES** built solely for the purpose of executing controlled comparative tests against `EvidenceContract_v1`.  
> They do **NOT** represent finalized production application code. A production observation adapter will be designed only after a candidate observation engine is benchmarked, evaluated, and formally selected via an approved Architectural Decision Record (ADR).

---

## 2. Output Format Verification Requirement

Candidate observation engines produce output structures that depend heavily on software version, installed plugins, host OS, and ingest module configurations.

Output formats must **NOT** be assumed guaranteed before testing:
* **Autopsy Expected Outputs (To Be Verified):** SQLite database (`autopsy.db`), CASE-UCO JSON reports, XML/HTML report exports, carved media in `ModuleOutput/`.
* **IPED Expected Outputs (To Be Verified):** `iped-output.json`, HTML/CSV reports, Lucene index files, carved media subdirectories.

During benchmark setup, the benchmark adapter must perform an explicit **Output Format Discovery** step to record which output structures were actually produced by the candidate engine version under test.

## 3. Experimental Benchmark Adapter Interface

All candidate benchmark adapters implement a uniform abstract Python boundary:

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass
from pathlib import Path
from typing import Dict, Any, List

@dataclass
class DiscoveredOutputFormats:
    engine_name: str
    engine_version: str
    has_sqlite_db: bool
    has_case_uco_json: bool
    has_iped_json: bool
    has_csv_exports: bool
    discovered_files: List[Path]

@dataclass
class ObservationJobResult:
    execution_time_sec: float
    exit_code: int
    was_headless: bool
    peak_ram_mb: float
    avg_cpu_percent: float
    output_size_mb: float
    discovered_formats: DiscoveredOutputFormats

class BaseBenchmarkObservationAdapter(ABC):
    """
    Experimental Benchmark Adapter Boundary.
    Insulates benchmark evaluation scripts from candidate engine output formats.
    """
    
    @abstractmethod
    def run_observation(self, image_path: Path, output_dir: Path) -> ObservationJobResult:
        """Executes candidate observation engine CLI tool."""
        pass

    @abstractmethod
    def discover_outputs(self, output_dir: Path) -> DiscoveredOutputFormats:
        """Inspects and verifies output formats actually generated by the engine."""
        pass

    @abstractmethod
    def normalize_to_evidence_contract(self, output_dir: Path) -> Dict[str, Any]:
        """
        Parses discovered output files and emits Normalized Evidence Contract (v1) JSON.
        Downstream analysis consumes ONLY this emitted contract.
        """
        pass
```

## 4. Candidate Adapter Specifications

### A. Autopsy Benchmark Adapter (`AutopsyBenchmarkAdapter`)
1. **Execution:** Invokes `autopsy64.exe --inputPath="<image>" --caseName="<case>" --runFromCommandLine=true`.
2. **Output Discovery:** Checks for presence of `autopsy.db`, CASE-UCO JSON, and carved media directories.
3. **Normalization Strategy:**
   * *Primary Path:* Query `autopsy.db` SQLite tables (`tsk_files`, `blackboard_artifacts`, `blackboard_attributes`).
   * *Secondary Path (Fallback):* Parse CASE-UCO JSON report if generated.
   * *Emit:* `EvidenceContract_v1` JSON structure with complete provenance (`source_path`, `byte_offset`, `sha256`, `timestamps`).

### B. IPED Benchmark Adapter (`IPEDBenchmarkAdapter`)
1. **Execution:** Invokes `iped -d <image> -o <output_dir>`.
2. **Output Discovery:** Checks for presence of `iped-output.json`, CSV metadata summaries, and carved media outputs.
3. **Normalization Strategy:**
   * *Primary Path:* Parse `iped-output.json` entries.
   * *Secondary Path (Fallback):* Parse CSV report exports.
   * *Emit:* `EvidenceContract_v1` JSON structure with complete provenance (`source_path`, `byte_offset`, `sha256`, `timestamps`).

---

## 5. Architectural Isolation Guarantee

Downstream evaluation scripts consume **only** the `EvidenceContract_v1` JSON dict produced by `normalize_to_evidence_contract()`. Downstream benchmarking code is strictly decoupled from Autopsy SQLite tables, IPED internal JSON formats, or any candidate engine internals.
